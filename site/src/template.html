Jackintosh

Switch on your Atari. A Macintosh Plus comes up.

The genuine Mac Plus ROM runs on the Atari's own 68000: the happy Mac, System 6, the Finder and the software of 1986 to 1990, from disk images on a microSD card. No TOS, no emulator: from power-on, the Atari is the Mac.

Build your image First steps How it works

For the Atari ST, STF, STFM and Mega ST, and the STE and Mega STE, with a monochrome monitor.

Why “Jackintosh”

In 1985 Jack Tramiel, who had just bought Atari, launched the ST: a 68000, a mouse, a windowed desktop and a sharp monochrome screen, at a fraction of the Macintosh's price. The press called it the “Jackintosh”. Forty years later the joke comes true: with the right ROM in its sockets, the ST boots as a Macintosh Plus. Jack is watching.

What you need

  • An Atari of the ST or STE family and a monochrome monitor: an SM124, or any mono display.
  • The SidecarTridge TOS Emulator in the TOS ROM sockets, to serve the Jackintosh image as the Atari's ROM.
  • The SidecarTridge Multi-device in the cartridge port, running the md-jackintosh microfirmware: floppies, hard disk, clock and PRAM.
  • Your own Mac Plus ROM, the 128 KB v3. Apple's code is never distributed here.

What you get

  • Apple's own Mac Plus ROM, patched in place, at full Atari speed.
  • 640×400 on the mono monitor, or the classic 512×342 framed in black.
  • Up to 4 MB of Mac RAM.
  • Floppies and a hard disk from the microSD card, chosen in a menu at power-on.
  • The clock from the network, and the Mac's settings kept on the card.
  • Sound on the STE and Mega STE; the Mega STE at 16 MHz with its cache.
  • US, French, German, Spanish and UK Atari keyboards.

First steps

Your image is on the TOS Emulator and the Multi-device runs md-jackintosh. Now give the Mac a System: start it from a floppy, then put it on a hard disk.

Start System 6.0.8 from a floppy

  1. Get System 6.0.8

    Download MacOS 6.0.8 US 800K from hampa.ch and unpack it: 7-Zip on Windows, The Unarchiver or Keka on macOS, 7z on Linux. You get four floppies.

    Copy them to the /jackintosh folder of the Multi-device's microSD card.

  2. Choose the startup floppy

    Switch the Atari on. In the Jackintosh menu press A, pick disk1.image.bin (System Tools) and press Space.

    Press E, or let the countdown run out.

  3. You are on the Mac

    The happy Mac, then the Finder with System Tools on the desktop.

    Control is the Mac's Command key: Control+E ejects the floppy.

Put System 6.0.8 on a hard disk

  1. Put the blank hard disk on the card

    Download Jackintosh-HD-20MB.dsk.zip, an empty 20 MB Mac volume, unzip it and copy Jackintosh-HD-20MB.dsk to /jackintosh.

  2. Choose both disks

    In the menu: A for System Tools in FD0, I for the hard disk in HD0. Then E.

  3. Both on the desktop

    The Mac starts from the floppy, since the hard disk has no System yet. Jackintosh HD sits under System Tools.

  4. Drag the System Folder across

    Open System Tools and drag its System Folder onto Jackintosh HD. The Finder copies it and makes the hard disk a startup disk.

  5. Start from the hard disk

    Choose Restart in the Special menu. In the Jackintosh menu press Shift+A to empty FD0, then E.

  1. Line up the floppies

    Put the blank hard disk on the card as in the quick way. In the menu choose HD0 and FD0 as there, then press Control+A and put disk3.image.bin (Utilities 2) in slot 2 and disk2.image.bin (Utilities 1) in slot 3.

  2. Open the Installer

    Press E. The Mac starts from System Tools: open it, open the Installer and click OK.

  3. Skip Easy Install

    Easy Install finds no matching configuration: the Jackintosh serves its hard disk the way a Mac serves a floppy. Click Customize.

  4. Choose the System

    Click System software for any Macintosh, check that the disk is Jackintosh HD (Switch Disk otherwise) and click Install.

  5. Feed it floppies with SELECT

    When the Installer asks for a disk, it has already ejected the floppy: press the Multi-device's SELECT button. It wants Utilities 2, Utilities 1, then System Tools again; SELECT wraps from slot 3 to slot 1.

  6. Done

    Click Quit and restart. In the Jackintosh menu press Shift+A to empty FD0, then E: the full System 6.0.8 starts from the hard disk.

Every step above was run in Hatari, each way ending in a start from the hard disk alone. A hard disk image is a plain file on the card: copy it somewhere safe before big changes.

How it works

A tour of the 68000's 16 MB address space, from power-on to the Finder. Every trick that turns an Atari into a Mac Plus happens at an address: the list beside you shows where you are.

What we call “the glue”

The Jackintosh image is two things back to back: Apple's Mac Plus ROM, which is yours, and about 35 KB of our own 68000 code in front of it. That code is the glue, because it glues the Mac ROM to Atari hardware.

  • It starts the Atari at power-on: sizes the RAM, sets up the screen, greets the Multi-device and shows the menu.
  • It then hands over to the Mac ROM, and stands in for every Mac chip the Atari lacks: the timers, the clock, the keyboard, the floppy drive, the sound.
  • The ROM calls it through small patches, each replacing a few bytes of Apple's code with a jump into the glue.

Not to be confused with the Atari ST's GLUE chip, the custom chip on the motherboard that decodes addresses and makes the video timing. That chip keeps doing its job, untouched; our glue is software in the ROM.

    Each chapter starts at an address of the 68000's 16 MB. Dashed: addresses where a Mac Plus has chips and an Atari has nothing.

    Same CPU, different computer

    The Mac Plus and the Atari ST are close cousins: same processor, same era, both with a mouse and a monochrome screen. That is what makes a Jackintosh possible.     Why not just emulate?

    An emulator is a program that pretends to be a Mac, running on TOS and translating every access to the Mac's chips; it costs speed at every step. The Jackintosh does the opposite: the Atari's own 68000 runs Apple's ROM at full speed, and only where that code would touch a Mac chip does the glue step in. It does so in three ways, cheapest first:

    1. Patch the ROM where it touches hardware: a few bytes replaced by a jump into the glue, the same length, so every other byte stays where Apple put it.
    2. Keep copies of the Mac's chips in RAM, where the ROM reaches them through pointers it reads from memory: the glue points those at its copies and plays the chips' part.
    3. Catch what is left: a program that writes where an Atari has nothing gets a bus error, and the glue's handler skips or re-runs that one instruction.

    System 6's absolute addresses

    System 6.0.8 fixes bugs in the Plus ROM with its own code, and that code calls the ROM at absolute addresses: $40xxxx, where a Mac Plus has its ROM. On an Atari the ROM is elsewhere. So as each System resource loads, the glue checks it (type, ID, size, SHA-256) and moves every listed address to where the ROM really is.

    Nil pointers

    Mac programs write through nil pointers all the time: on a Mac that lands in RAM at address 0 and nobody notices. On an Atari, address 0 is ROM and the write is a bus error. The glue's handler finds the instruction and skips it. Step through an example (our own code, not Apple's).

      MOVEA.L  handle,A0     ; A0 = 0 (no memory)  MOVE.L   D0,4(A0)      ; write to $000004  ADDQ.W   #1,D1  RTS

    The Multi-device

    The cartridge port can only be read by the Atari. So to send a word, the Atari reads an address that encodes it: $FB0000 plus the word. The Multi-device's RP2040 watches the addresses and answers by writing into a 64 KB window the Atari reads at $FA0000. Step through a disk read.
